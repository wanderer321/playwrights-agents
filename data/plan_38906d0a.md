根据项目信息分析，该项目为一个大型原生微信小程序（页面数高达728个，可能包含丰富的活动模板或复杂的后台管理功能）。以下是基于Minium框架的测试计划。

```markdown
# Test Plan: pure-activity

## Overview
- **项目名称**: pure-activity
- **框架类型**: 原生微信小程序
- **项目规模**: 大型 (728个页面, 5个自定义组件)
- **测试工具**: Minium (微信官方自动化测试框架)
- **测试策略**: 鉴于页面数量巨大，测试将侧重于核心业务流程（P0级）、微信特有功能交互以及关键组件的稳定性。采用PO（Page Object）模式设计测试用例，以便维护。

## Suite: 01_用户授权与登录模块
该模块主要测试小程序的入口权限获取，是所有业务流程的前置条件。

### TC-AUTH-001: 微信授权登录
- **Steps**:
  1. 启动小程序，监听首页 `onLoad` 事件。
  2. 检测页面是否包含 `<button open-type="getUserInfo">` 或使用最新的头像昵称填写能力。
  3. 模拟用户点击授权按钮。
  4. 调用 `mini.mockWxMethod` 模拟 `wx.getUserProfile` 或 `wx.getUserInfo` 返回成功。
  5. 验证本地缓存是否有 `token` 或用户信息。
- **Expect**: 成功获取用户信息，页面跳转至活动列表页或首页，无报错弹窗。

### TC-AUTH-002: 手机号授权绑定
- **Steps**:
  1. 进入用户中心或需要身份验证的页面。
  2. 点击“绑定手机号”按钮 (`open-type="getPhoneNumber"`)。
  3. 模拟微信接口返回加密数据。
  4. 后端解密成功后，检查页面显示的手机号是否正确。
- **Expect**: 手机号成功绑定，界面显示脱敏后的手机号。

## Suite: 02_活动浏览与核心业务
针对项目名称 "pure-activity"，推测核心业务为活动的展示、搜索与参与。

### TC-ACT-001: 活动列表加载与分页
- **Steps**:
  1. 进入活动列表页面。
  2. 验证首屏数据加载，检查列表长度大于0。
  3. 使用 `mini.page.scroll_to(9999)` 模拟页面滚动到底部。
  4. 监听触底事件 `onReachBottom`，验证是否发起下一页请求。
  5. 检查列表数据是否追加。
- **Expect**: 列表数据正常展示，下拉刷新正常，上拉加载更多无重复数据或报错。

### TC-ACT-002: 活动详情页渲染
- **Steps**:
  1. 从列表页随机点击一个活动卡片。
  2. 跳转至详情页，获取页面路径参数 `id`。
  3. 检查关键元素：活动标题、时间、地点、价格是否渲染。
  4. 检查富文本或自定义组件内容是否正常显示。
- **Expect**: 详情页内容与后台配置一致，图片加载正常，无布局错乱。

## Suite: 03_支付与订单模块
涉及微信支付能力，需重点测试支付状态机的流转。

### TC-PAY-001: 创建订单并发起支付
- **Steps**:
  1. 在活动详情页点击“立即报名”或“购买”。
  2. 填写必要表单信息（如姓名、身份证等）。
  3. 点击提交，拦截 `wx.request` 检查订单创建接口。
  4. 模拟调用 `wx.requestPayment`。
  5. 使用 `mini.mockWxMethod` 模拟支付成功回调。
- **Expect**: 订单状态变更为“待支付”后成功跳转支付，支付成功后订单状态更新为“已支付”，并跳转至成功页。

### TC-PAY-002: 支付取消或失败处理
- **Steps**:
  1. 重复 TC-PAY-001 步骤至发起支付。
  2. 模拟用户点击取消支付。
  3. 检查页面提示及订单状态。
- **Expect**: 订单保留在“待支付”状态，提示用户“支付取消”，并提供重新支付的入口。

## Suite: 04_分享与社交裂变
微信小程序的核心传播能力测试。

### TC-SHARE-001: 转发给好友
- **Steps**:
  1. 进入活动详情页。
  2. 点击右上角菜单“转发”或页面内的分享按钮。
  3. 检查 `onShareAppMessage` 定义的 `title`, `path`, `imageUrl`。
  4. 模拟分享成功回调。
- **Expect**: 分享卡片标题、图片配置正确，路径参数包含分享者ID（如有）。

### TC-SHARE-002: 生成活动海报
- **Steps**:
  1. 点击“生成海报”按钮。
  2. 监听 `wx.createCanvasContext` 或新版的 Canvas 2D API 调用。
  3. 验证生成的临时图片路径。
  4. 模拟 `wx.saveImageToPhotosAlbum` 保存到相册。
- **Expect**: 海报生成无报错，图片包含活动信息及用户二维码，保存相册权限申请逻辑正常。

## Suite: 05_定位与地图服务
如果活动涉及线下地点，此模块必不可少。

### TC-LOC-001: 获取当前位置
- **Steps**:
  1. 进入活动地图导航页。
  2. 调用 `wx.getLocation`。
  3. Mock 返回经纬度数据。
  4. 检查地图组件 `<map>` 是否定位到正确位置。
- **Expect**: 地图中心点移动到当前位置，无定位失败弹窗（或引导开启权限）。

### TC-LOC-002: 导航功能
- **Steps**:
  1. 点击“导航”按钮。
  2. 拦截 `wx.openLocation` 调用。
  3. 验证传入的经纬度和地址名称是否正确。
- **Expect**: 成功唤起腾讯地图或其他地图App进行导航规划。

## Suite: 06_异常与兼容性测试
针对原生框架及多页面特性的补充测试。

### TC-SYS-001: 网络异常处理
- **Steps**:
  1. 使用 `mini.mockRequest` 拦截所有请求并返回网络错误。
  2. 操作小程序进行数据加载。
  3. 检查是否有友好的错误提示（如“网络开小差了”）。
- **Expect**: 小程序不崩溃，不显示 undefined，提供重试按钮。

### TC-SYS-002: 页面栈深度测试
- **Steps**:
  1. 编写循环脚本，连续 push 进入 10 个不同的页面。
  2. 检查页面栈是否溢出（微信限制页面栈 10 层）。
  3. 验证第 10 层页面是否使用了 `wx.redirectTo` 或 `wx.reLaunch`。
- **Expect**: 页面跳转逻辑正确，未触发页面栈溢出错误。
```
