# Expanded Test Plan: zhihui-workshop (智慧工坊)

## Overview
Based on the project structure analysis, **zhihui-workshop** is a React-based intelligent workshop platform focusing on image processing services. The application consists of six core modules: **Home** (Dashboard), **Hall** (Exhibition/Showcase), **ID Photo** (ID photo generation), **Photo** (General photo processing), **Poster** (Poster design), and **Orders** (Order management).

This test plan provides maximum coverage including happy paths, boundary conditions, negative scenarios, state transitions, and cross-module integration flows.

---

## Suite: Home (Dashboard/Landing)
*Primary entry point for user navigation and status overview.*

### TC-HOME-001: Initial Page Load and Navigation
- **Category**: happy-path
- **Steps**: Navigate to root URL; wait for page load; verify all navigation cards/buttons are visible; click each navigation item.
- **Expect**: Page loads within 3s; all module entry points (ID Photo, Poster, etc.) are clickable and navigate correctly.

### TC-HOME-002: Empty State for New User
- **Category**: empty
- **Steps**: Login with a newly registered user with zero history; observe the dashboard "Recent Orders" or "Activity" section.
- **Expect**: Displays friendly empty state illustration and guidance text (e.g., "No orders yet, start creating!"); no broken images or `undefined` text.

### TC-HOME-003: Rapid Module Switching
- **Category**: concurrent
- **Steps**: Rapidly click between Home, Hall, and Orders tabs in quick succession (5 clicks in 2 seconds) without waiting for load.
- **Expect**: UI handles the cancellation of previous navigation requests gracefully; final rendered page matches the last clicked tab; no memory leaks or console errors.

### TC-HOME-004: Network Failure Resilience
- **Category**: negative
- **Steps**: Open browser dev tools, set network to "Offline"; refresh the Home page.
- **Expect**: Application displays a "Network Error" or "Unable to connect" toast/modal instead of a white screen; retry button functions correctly when network is restored.

### TC-HOME-005: Responsive Layout Verification
- **Category**: ui
- **Steps**: Resize viewport from 1920px width down to 375px (mobile); observe grid layout of feature cards.
- **Expect**: Cards reflow properly (e.g., 4 columns -> 1 column); no horizontal scroll bar appears; text remains legible without overlap.

### TC-HOME-006: Session Expiry Handling
- **Category**: state
- **Steps**: Leave the Home page idle until session token expires (or manually clear token); attempt to click a feature.
- **Expect**: User is redirected to login page or shown a session expiry modal; current state is not lost if possible (or gracefully reset).

## Suite: ID Photo (ID Photo Generation)
*Core feature for automated ID photo processing.*

### TC-IDP-001: Standard ID Photo Generation Flow
- **Category**: happy-path
- **Steps**: Upload a valid portrait image (JPG, 2MB); select standard specification (e.g., 1-inch, 295x413px); click "Process"; download result.
- **Expect**: Image uploads successfully; preview shows cropping area; processed image matches dimensions; download triggers automatically or via button.

### TC-IDP-002: Invalid File Format Upload
- **Category**: negative
- **Steps**: Attempt to upload a `.txt`, `.pdf`, or `.exe` file via the upload button.
- **Expect**: File picker filters non-image types; if bypassed, UI shows immediate validation error "Unsupported file format" and prevents upload.

### TC-IDP-003: Maximum File Size Boundary
- **Category**: boundary
- **Steps**: Upload an image exactly at the size limit (e.g., 10MB) and one just above (10.1MB).
- **Expect**: Limit image uploads successfully; image above limit triggers "File too large" error message.

### TC-IDP-004: Non-Human/Face Detection Failure
- **Category**: negative
- **Steps**: Upload an image of a landscape, a pet, or a group photo with multiple faces.
- **Expect**: System detects no face or multiple faces; displays specific error message (e.g., "No face detected, please upload a portrait"); processing is halted.

### TC-IDP-005: Browser Refresh During Processing
- **Category**: state
- **Steps**: Upload image, start processing, and immediately hit F5 (Refresh).
- **Expect**: On reload, the app does not attempt to resume the incomplete server-side job (stateless); user is returned to initial upload state.

### TC-IDP-006: Double-Submit Prevention
- **Category**: concurrent
- **Steps**: Upload image and rapidly click the "Process" button 5 times.
- **Expect**: Button is disabled after first click; only one API request is sent; only one credit/order is generated.

### TC-IDP-007: Background Color Switching
- **Category**: happy-path
- **Steps**: Process an ID photo; switch background color from Blue to Red to White using the color picker.
- **Expect**: Preview updates instantly (or with minimal delay); final download reflects the selected background color.

## Suite: Photo (General Photo Editing)
*Generic photo enhancement or editing tools.*

### TC-PHO-001: Basic Photo Edit and Save
- **Category**: happy-path
- **Steps**: Upload photo; apply a filter (e.g., B&W); adjust brightness slider; save/download.
- **Expect**: Changes apply in real-time; downloaded file contains the edits.

### TC-PHO-002: Undo/Redo State Management
- **Category**: state
- **Steps**: Apply 3 distinct changes (Crop, Filter, Rotate); click Undo 3 times; click Redo 2 times.
- **Expect**: UI state history is managed correctly; Undo reverts to original step-by-step; Redo reapplies correctly.

### TC-PHO-003: Corrupted Image Handling
- **Category**: negative
- **Steps**: Rename a `.txt` file to `.jpg` (corrupting header) and upload.
- **Expect**: Frontend or backend decoder catches the error; displays "Unable to read file" instead of crashing the canvas/renderer.

### TC-PHO-004: Extreme Aspect Ratio Crop
- **Category**: boundary
- **Steps**: Upload a standard image; use crop tool to select a 1px x 1000px vertical strip.
- **Expect**: Crop tool allows selection; system warns or handles extreme aspect ratios without rendering errors.

### TC-PHO-005: Mobile Viewport Interaction
- **Category**: ui
- **Steps**: On mobile viewport, attempt to use sliders and crop handles.
- **Expect**: Touch targets are large enough (min 44px); sliders respond to touch drag; canvas doesn't scroll the page while drawing crop area.

## Suite: Poster (Poster Design)
*Template-based design tool.*

### TC-POS-001: Create Poster from Template
- **Category**: happy-path
- **Steps**: Select a template from the library; replace placeholder text; upload a custom image; save draft.
- **Expect**: Template loads correctly; text editing works; image replaces placeholder; draft saves to server.

### TC-POS-002: Text Overflow Handling
- **Category**: boundary
- **Steps**: Select a text box with limited space; paste a 500-word paragraph.
- **Expect**: Text is truncated visually with ellipsis (...) or box expands without breaking layout; no text spill outside container.

### TC-POS-003: XSS Injection in Text Fields
- **Category**: negative
- **Steps**: Enter `<script>alert('xss')</script>` into a poster text field; save and reload.
- **Expect**: Script is sanitized and displayed as plain text or stripped; alert does not execute.

### TC-POS-004: Missing Font Fallback
- **Category**: ui
- **Steps**: Use a specific font (e.g., "FancyFont"); load page on a device without that font.
- **Expect**: System falls back to a default sans-serif font gracefully; layout does not break.

### TC-POS-005: Auto-Save Recovery
- **Category**: state
- **Steps**: Make edits to a poster; close the tab accidentally (simulate crash); reopen the editor.
- **Expect**: Application detects auto-saved draft and prompts "Restore unsaved changes?".

### TC-POS-006: Cross-Module Image Import
- **Category**: cross-module
- **Steps**: Go to ID Photo module, create an ID photo; go to Poster module; attempt to import the recently created ID photo.
- **Expect**: Recent images are accessible in the media picker; image imports with correct resolution.

## Suite: Orders (Order Management)
*Transaction history and payment status.*

### TC-ORD-001: View Order History
- **Category**: happy-path
- **Steps**: Navigate to Orders; verify list of past transactions.
- **Expect**: Orders are sorted by date (newest first); status (Paid/Pending/Failed) is clearly visible.

### TC-ORD-002: Pagination/Infinite Scroll
- **Category**: boundary
- **Steps**: Ensure account has > 20 orders; scroll to bottom of list.
- **Expect**: Next page loads automatically or pagination controls work; no duplicate entries at boundary.

### TC-ORD-003: Payment Retry Flow
- **Category**: state
- **Steps**: Locate an order with status "Payment Failed"; click "Retry Payment"; complete payment.
- **Expect**: Status updates to "Paid" without creating a duplicate order ID.

### TC-ORD-004: Deep Linking to Non-Existent Order
- **Category**: negative
- **Steps**: Navigate directly to URL `/orders/999999` (non-existent ID).
- **Expect**: Application handles 404 gracefully; displays "Order not found" message instead of blank screen or loader loop.

### TC-ORD-005: Filter and Sort Consistency
- **Category**: ui
- **Steps**: Apply filter "Completed"; sort by "Price High to Low"; refresh page.
- **Expect**: (Ideally) Filters persist via URL params; if not, filters reset to default cleanly.

### TC-ORD-006: Order Creation from ID Photo
- **Category**: cross-module
- **Steps**: Process an ID Photo; complete checkout; go to Orders page.
- **Expect**: New order appears at the top of the list; details match the processed item.

## Suite: Hall (Exhibition/Showcase)
*Public gallery or template showcase.*

### TC-HAL-001: Browse Gallery
- **Category**: happy-path
- **Steps**: Load Hall page; scroll through gallery items.
- **Expect**: Images lazy load; placeholders shown while loading; layout remains stable after images load (no layout shift).

### TC-HAL-002: Search with Special Characters
- **Category**: negative
- **Steps**: Enter search query `!@#$%^&*()` or SQL injection string `' OR 1=1 --`.
- **Expect**: API handles query safely; returns empty result set or sanitized results; no database error exposed to UI.

### TC-HAL-003: Broken Image Link Handling
- **Category**: negative
- **Steps**: Simulate a broken image link (via network throttling/blocking specific asset).
- **Expect**: A fallback placeholder image (broken icon) is displayed; UI grid does not collapse.

### TC-HAL-004: Deep Link to Specific Item
- **Category**: state
- **Steps**: Click a specific item in the Hall; copy URL; open in new incognito window.
- **Expect**: Item details load directly without requiring navigation from the main list.

### TC-HAL-005: Empty Gallery State
- **Category**: empty
- **Steps**: Apply a filter that matches no results (e.g., Date: Year 2050).
- **Expect**: Displays "No results found" message; search bar remains functional.

## Suite: Global & Cross-Cutting Concerns

### TC-GLB-001: Browser Back Button Navigation
- **Category**: state
- **Steps**: Navigate Home -> ID Photo -> Orders; click Browser Back button twice.
- **Expect**: History stack is respected; user lands on ID Photo then Home; state (e.g., form inputs) is cleared or preserved appropriately.

### TC-GLB-002: Concurrent Session Login
- **Category**: concurrent
- **Steps**: Login on Device A; Login on Device B with same credentials; perform action on Device A.
- **Expect**: Device A is either logged out with notification ("Session expired") or token is refreshed; data remains consistent.

### TC-GLB-003: Accessibility (a11y) Check
- **Category**: ui
- **Steps**: Run axe-core scan on all pages; Tab through navigation using keyboard only.
- **Expect**: No critical a11y violations; focus ring is visible on all interactive elements; logical tab order.

### TC-GLB-004: Language/Locale Switching
- **Category**: ui
- **Steps**: If supported, switch language to Chinese (zh-CN) or a long-text locale (e.g., German).
- **Expect**: UI text updates; layout accommodates longer text strings without breaking (no text overlap).
