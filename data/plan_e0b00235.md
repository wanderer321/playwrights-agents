# Test Plan: pure-activity

## Overview
- **Project Name**: pure-activity
- **Framework**: Native WeChat Mini Program
- **Scale**: Large (217 pages, 5 components)
- **Test Tool**: Minium (Python)

**Summary**:
Given the large scale of this project (217 pages), this test plan prioritizes critical business paths and WeChat-specific functionalities. The project name "pure-activity" suggests a focus on event management, activity listings, or social engagement. The testing strategy focuses on:
1.  **Core User Flow**: Login -> View Activity -> Register/Join -> Share.
2.  **WeChat Ecosystem Integration**: Authorization, Payment, Sharing, Location.
3.  **Stability**: Handling network exceptions and data boundaries.

---

## Suite: 00_Login_And_Authorization
*Critical path for user identity.*

### TC-AUTH-001: WeChat User Login Flow
- **Steps**:
    1. Launch the Mini Program.
    2. Check if the user is logged in (check storage/token).
    3. If not logged in, trigger the login button.
    4. Mock/Handle the `wx.getUserProfile` or `wx.login` API call.
    5. Verify the session is established.
- **Expect**: User successfully logs in, avatar/nickname display correctly, and token is stored locally.

### TC-AUTH-002: Location Authorization
- **Steps**:
    1. Navigate to a page requiring location (e.g., "Nearby Activities").
    2. Trigger the location API.
    3. Handle the system authorization popup (Allow/Deny).
    4. Verify behavior on both permission granted and denied.
- **Expect**: 
    - If Allowed: Map/Location shows current position.
    - If Denied: Graceful error message or default location placeholder is shown.

---

## Suite: 01_Home_And_Activity_List
*Core content display.*

### TC-HOME-001: Home Page Rendering
- **Steps**:
    1. Launch app to Home page.
    2. Verify that the Activity List component renders.
    3. Check for loading skeletons before data arrives.
- **Expect**: Page loads without layout shift, data renders correctly.

### TC-HOME-002: Activity List Pagination (Pull Down/Up)
- **Steps**:
    1. Scroll down to the bottom of the list to trigger `onReachBottom`.
    2. Verify loading indicator appears and new data is appended.
    3. Pull down to trigger `onPullDownRefresh`.
- **Expect**: 
    - Pagination loads the next page correctly.
    - Pull-down refresh resets the list to the latest data.

### TC-HOME-003: Activity Search
- **Steps**:
    1. Tap the search bar.
    2. Input a keyword (e.g., "Yoga").
    3. Submit search.
- **Expect**: List filters to show only activities matching the keyword.

---

## Suite: 02_Activity_Detail_And_Interaction
*The core business logic.*

### TC-DETAIL-001: View Activity Detail
- **Steps**:
    1. Click an item from the Activity List.
    2. Navigate to the Detail page.
    3. Verify all elements load: Images, Title, Time, Location, Description.
- **Expect**: All data matches the backend response; no broken images.

### TC-DETAIL-002: Activity Registration/Sign Up
- **Steps**:
    1. On the Detail page, click the "Sign Up" or "Join" button.
    2. If a form is required, fill in mandatory fields.
    3. Submit the form.
- **Expect**: 
    - Success toast message appears.
    - Button state changes to "Already Joined" or similar.
    - User appears in the participant list (if visible).

### TC-DETAIL-003: Share Activity
- **Steps**:
    1. Click the "Share" button (top right menu or inline button).
    2. Select "Share to Friends" or "Share to Timeline".
- **Expect**: 
    - `onShareAppMessage` triggers correctly.
    - Share card displays correct title and image.

---

## Suite: 03_Payment_And_Order
*Financial transactions.*

### TC-PAY-001: Payment Flow Simulation
- **Steps**:
    1. Initiate a paid activity registration.
    2. Click "Pay Now".
    3. Mock the `wx.requestPayment` API response (Success/Fail/Cancel).
- **Expect**: 
    - Success: Order status updates to "Paid", user receives success notification.
    - Fail/Cancel: Order remains "Unpaid", user sees appropriate error message.

### TC-PAY-002: Order List View
- **Steps**:
    1. Navigate to User Center -> My Orders.
    2. Verify list of historical orders.
    3. Click an order to view details.
- **Expect**: Order history is accurate; navigation to detail page works.

---

## Suite: 04_User_Center
*User profile and settings.*

### TC-USER-001: User Profile Update
- **Steps**:
    1. Navigate to User Profile page.
    2. Click "Edit Profile".
    3. Update nickname or avatar.
    4. Save changes.
- **Expect**: Changes persist and are reflected immediately in the UI.

### TC-USER-002: Feedback/Contact Support
- **Steps**:
    1. Navigate to "Help" or "Feedback".
    2. Submit a text feedback.
- **Expect**: Feedback submits successfully without crash.

---

## Suite: 05_Components_Unit_Test
*Testing the 5 reusable components.*

### TC-COMP-001: Component Rendering Props
- **Steps**:
    1. Isolate each of the 5 components in a test page.
    2. Pass various prop combinations (valid data, empty data, long text).
- **Expect**: Components render UI correctly based on props without throwing JS errors.

### TC-COMP-002: Component Event Triggering
- **Steps**:
    1. Interact with the component (e.g., click a button inside a component).
    2. Verify if the component triggers the expected custom event (e.g., `bindtap`).
- **Expect**: Parent page receives the event and payload correctly.
